Rules and how I measure success

No file ever gets deleted, and I track four numbers to check that it's working.

Rules

  • Never delete. When a new version arrives, the old one moves to an archive folder.
  • When unsure, ask. A file it can't place goes on a review list instead of a guess.
  • One naming style for every file: course, unit, topic and type.
  • Follow Brightspace's rules. Its terms don't allow bots, so I still download files myself.

How I measure success

  • Automation rate: the share of course files filed without my help.
  • Review list: how many files are waiting for me.
  • Lost files: files deleted or overwritten. The goal is zero.
  • Full log: every move is recorded, so anything can be undone.

How it works

The system sorts files on its own and only asks me when it isn't sure where one goes.

The auto-filer

A small program that wakes up whenever a file lands in my downloads folder. It reads the file name, the folder and the first page to figure out the course, then renames and files it.

The Drive checker

An AI agent that checks my professor's Google Drive at 7am and 7pm and downloads anything new or updated.

The review list

Anything the auto-filer can't place goes on a short list with a note on why. I fix the name, and it gets filed the next time.

Testing

33 automated tests check every change, and I asked a second AI model, Codex, to look for weak spots. It found eight.

FixedTwo files with the same name could overwrite each other. Now an existing file is never replaced.
FixedA crash could corrupt the list of files already downloaded. It is now saved safely.
FixedThe same file used in two courses was skipped as a duplicate. Now it only counts as a duplicate within one course.
FixedWhen several versions arrived together, an older one could end up as the current copy. Now the newest always wins.
FixedIf replacing a file failed halfway, the current copy could go missing. Now it is put back.
Not a bugLoose name matching looked risky, but it is what lets a file called "Module_6_Homework.pdf" update the right homework. A test now makes sure it keeps working.
Not neededTwo issues only matter for Google Docs files and very large zip files. My professor's folder has neither, so I'll fix them if that changes.
From the dataTemporary copies that Word and Excel create while a file is open kept landing on the review list. The system now ignores them.
